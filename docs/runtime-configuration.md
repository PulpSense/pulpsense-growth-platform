`.github/workflows/softphone-pages.yml` verifies softphone changes and publishes a branch deployment for each non-draft pull request. A merge to `master` cancels any stale softphone run, waits for the repository's Production approval, and uploads the exact verified commit to the `pulpsense-softphone-preview` Pages project on its `master` branch. The custom `softphone.pulpsense.com` hostname follows that production branch.

## Environment isolation checks

- Preview and local funnel environments must use the Trigger.dev Development key and non-production downstream credentials. Funnel events keep the `preview` label so the automation worker can enforce destination isolation; that label does not select a Trigger.dev Preview branch.
- Preview Astro builds must set `PUBLIC_PULPSENSE_ENVIRONMENT=preview`, omit both campaigns' Pixel IDs, and use an explicit non-production Cal event. Both opaque campaign routes are generated together, and browser Meta tracking is enabled only by the production build.
- In production, browser tracking loads after the first interaction or a two-second idle fallback; verify passive `PageView` delivery against each live campaign dataset during the controlled release smoke test.
- Production secrets must not be exposed to browser code or variables prefixed for public bundling.
- Never copy values from ignored `.env` files into documentation, commits, logs, or issue comments.
- Before deploying, verify required keys in the hosting and Trigger.dev dashboards; repository presence proves names and defaults, not that remote values are configured.
